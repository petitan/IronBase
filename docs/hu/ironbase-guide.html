Mi az IronBase?

Az IronBase egy nagy teljesítményű, beágyazott NoSQL dokumentum adatbázis, Rust nyelven írva. MongoDB-kompatibilis API-t biztosít SQLite egyszerűségével - egyetlen fájl, szerver nélkül, nulla konfiguráció.

📄 Single-File

Egyetlen .mlite fájl tartalmazza az összes adatot, indexet és metaadatot.

🚀 Gyors

~200K insert/sec, ~500K indexed query/sec teljesítmény.

🔍 Keresés

B+ tree, fuzzy, full-text és semantic (RAG) keresés.

🔒 ACID

Tranzakciók WAL-lal, crash recovery, Read Committed izolációval.

Főbb jellemzők

Kategória Jellemzők
Query 21 query operator ($eq, $gt, $regex, $fuzzy, stb.)
Update 7 update operator ($set, $inc, $push, stb.)
Aggregation $match, $group, $project, $sort, $limit, $skip
Indexek B+ tree, compound, sparse, unique, fuzzy, fulltext
Keresés Fuzzy (3 algoritmus), Full-text (TF-IDF), RAG (FastText+HNSW)
Nyelvek Rust, Python (PyO3), C# (.NET 8)
MCP 70+ tool AI asszisztenseknek (HTTP + stdio)

Telepítés és indítás

HTTP mód (szerver)

# Build
cd mcp-server && cargo build --release

# Indítás
./target/release/mcp-ironbase-server

# Eredmény:

Query Operators - Comparison

Összehasonlító operátorok értékek szűrésére.

Operator Leírás Példa
$eq Egyenlő {"age": {"$eq": 25}} vagy {"age": 25}
$ne Nem egyenlő {"status": {"$ne": "deleted"}}
$gt Nagyobb mint {"price": {"$gt": 1000}}
$gte Nagyobb vagy egyenlő {"age": {"$gte": 18}}
$lt Kisebb mint {"score": {"$lt": 50}}
$lte Kisebb vagy egyenlő {"quantity": {"$lte": 10}}
$in Benne van a listában {"status": {"$in": ["active", "pending"]}}
$nin Nincs benne a listában {"role": {"$nin": ["banned", "deleted"]}} 
// Összetett példa: 18-65 év közötti aktív felhasználók
{
  "filter": {
    "age": {"$gte": 18, "$lte": 65},
    "status": {"$in": ["active", "verified"]},
    "deleted_at": {"$eq": null}
  }
}

Query Operators - Logical

Operator Leírás Példa
$and Minden feltétel igaz {"$and": [{...}, {...}]}
$or Legalább egy igaz {"$or": [{...}, {...}]}
$not Tagadás {"age": {"$not": {"$lt": 18}}}
$nor Egyik sem igaz {"$nor": [{...}, {...}]} 
// Admin VAGY moderátor és aktív
{
  "filter": {
    "$and": [
      {"$or": [
        {"role": "admin"},
        {"role": "moderator"}
      ]},
      {"status": "active"}
    ]
  }
}

Query Operators - Element

Operator Leírás Példa

$type Mező típusa {"age": {"$type": "number"}}

Típusok: string, number, boolean, array, object, null

Query Operators - Array

Operator Leírás Példa
$all Minden elem megtalálható {"tags": {"$all": ["rust", "db"]}}
$elemMatch Legalább egy elem illeszkedik {"items": {"$elemMatch": {"qty": {"$gt": 5}}}}
$size Tömb hossza {"tags": {"$size": 3}}

}

Query Operators - String

$regex - Reguláris kifejezés

// Email domain szűrés
{"email": {"$regex": "@gmail\\.com$"}}

// Név kezdőbetű (case sensitive)
{"name": {"$regex": "^K"}}

// Tartalmazza (case insensitive workaround: lowercase index)
{"name_lower": {"$regex": "kovács"}}

Query Operators - Special

$fuzzy - Fuzzy keresés

Hasonlósági alapú keresés elgépelések, variációk kezelésére.

// Egyszerű fuzzy (default: jaro_winkler, threshold: 0.8)
{"name": {"$fuzzy": "kovasc"}}

// Teljes konfiguráció
{"name": {"$fuzzy": {
  "value": "kovacs",
  "algorithm": "levenshtein",
  "threshold": 0.7
}}}

Algoritmusok:

Algoritmus Leírás Legjobb használat
jaro_winkler Gyors, előtag-érzékeny Nevek, rövid szövegek
levenshtein Edit distance Általános elgépelések
damerau_levenshtein Edit distance + átrendezés Betűcserék is ("kovacs" vs "koavcs")

$** - Wildcard (Recursive Descent)

Mező keresése bármilyen mélységben a dokumentumban.

// Keress "status" mezőt BÁRHOL a dokumentumban
{"$**.status": "active"}

// Találatok:
// {"status": "active"}                    ✓
// {"user": {"status": "active"}}          ✓
// {"data": {"info": {"status": "active"}}} ✓
⚠️ Teljesítmény

A $** mindig collection scan-t végez, nem használ indexet. Nagy collection-öknél kerülendő.

Operator Leírás Példa

│                    Aggregation Pipeline                         │

│                                                                 │
│  Documents  ─▶  $match  ─▶  $group  ─▶  $sort  ─▶  $limit      │

│                                                                 │
│  Példa:                                                         │

Pipeline Stages

Stage Leírás Példa
$match Dokumentumok szűrése {"$match": {"status": "active"}}
$group Csoportosítás és aggregálás {"$group": {"_id": "$city", "count": {"$sum": 1}}}
$project Mezők kiválasztása/átnevezése {"$project": {"name": 1, "total": "$amount"}}
$sort Rendezés {"$sort": {"total": -1}}
$limit Eredmények korlátozása {"$limit": 10}
$skip Eredmények kihagyása {"$skip": 20}

Accumulators

Accumulator Leírás Példa
$sum Összeg {"$sum": "$amount"} vagy {"$sum": 1} (count)
$avg Átlag {"$avg": "$price"}
$min Minimum {"$min": "$score"}
$max Maximum {"$max": "$score"}
$first Első érték {"$first": "$name"}
$last Utolsó érték {"$last": "$name"}

Tranzakciók

Az IronBase ACID tranzakciókat támogat WAL (Write-Ahead Log) alapon.

┌─────────────────────────────────────────────────────────────────┐
│                     Tranzakció életciklus                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  begin_transaction  ─▶  műveletek  ─▶  commit/rollback          │
│         │                  │                   │                │
│    WAL start           WAL write          WAL flush/clear       │
│                                                                 │
│  Izolációs szint: Read Committed                                │
│  Timeout: 5 másodperc (write lock)                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Tranzakció példa

// 1. Tranzakció indítása
{"name": "begin_transaction", "arguments": {}}

// 2. Műveletek
{
  "name": "update_one_tx",
  "arguments": {
    "collection": "accounts",
    "filter": {"_id": "acc1"},
    "update": {"$inc": {"balance": -1000}}
  }
}

{
  "name": "update_one_tx",
  "arguments": {
    "collection": "accounts",
    "filter": {"_id": "acc2"},
    "update": {"$inc": {"balance": 1000}}
  }
}

// 3a. Sikeres: commit
{"name": "commit_transaction", "arguments": {}}

// 3b. Hiba esetén: rollback
{"name": "rollback_transaction", "arguments": {}}

ACID tulajdonságok

Tulajdonság Implementáció
Atomicity WAL + rollback támogatás
Consistency Schema validation, unique constraints
Isolation Read Committed (egy writer, több reader)
Durability fsync + WAL CRC32 checksums

Best Practices

Pagination nagy adathalmazoknál

Collection: users (100,000 docs)
Page size: 1,000 docs

┌─────────────────────────────────────────────────────────────────┐
│ skip=0      │ skip=1000   │ skip=2000   │ ... │ skip=99000      │
│ limit=1000  │ limit=1000  │ limit=1000  │     │ limit=1000      │
├─────────────┼─────────────┼─────────────┼─────┼─────────────────┤
│ doc 0-999   │ doc 1K-1999 │ doc 2K-2999 │ ... │ doc 99K-100K    │
│ Page 1      │ Page 2      │ Page 3      │     │ Page 100        │
└─────────────────────────────────────────────────────────────────┘
        
// Skip/Limit pagination
{"filter": {}, "limit": 1000, "skip": 0}       // Page 1
{"filter": {}, "limit": 1000, "skip": 1000}    // Page 2
{"filter": {}, "limit": 1000, "skip": 2000}    // Page 3

// Cursor-based (gyorsabb nagy skip-nél)
{"filter": {"_id": {"$gt": "last_id"}}, "limit": 1000, "sort": [["_id", 1]]}

Index stratégia

💡 Index tippek
  • Indexelj gyakran szűrt mezőket
  • Compound index: bal-prefix szabály (a, b) → használható (a)-ra is
  • explain() használata query plan ellenőrzésre
  • Sparse index opcionális mezőkre
  • Unique index email, username mezőkre

OOM elkerülése

🚨 Kerülendő
  • find({}, {}) nagy collection-ön limit nélkül
  • Aggregation $match nélkül 100K+ dokumentumon
  • $push korlátlan tömb növelésre
💡 Ajánlott
  • Mindig használj limit-et find-nál
  • Aggregation pipeline elejére $match
  • Nagy eredményeknél projection a szükséges mezőkre
  • Streaming feldolgozás pagination-nel
