What is IronBase?

IronBase is a high-performance, embedded NoSQL document database written in Rust. It provides a MongoDB-compatible API with SQLite's simplicity - single file, serverless, zero configuration.

📄 Single-File

A single .mlite file contains all data, indexes, and metadata.

🚀 Fast

~200K insert/sec, ~500K indexed query/sec performance.

🔍 Search

B+ tree, fuzzy, full-text and semantic (RAG) search.

🔒 ACID

Transactions with WAL, crash recovery, Read Committed isolation.

Key Features

Category Features
Query 21 query operators ($eq, $gt, $regex, $fuzzy, etc.)
Update 7 update operators ($set, $inc, $push, etc.)
Aggregation $match, $group, $project, $sort, $limit, $skip
Indexes B+ tree, compound, sparse, unique, fuzzy, fulltext
Search Fuzzy (3 algorithms), Full-text (BM25), RAG (vLLM/BGE-M3+HNSW)
Languages Rust, Python (PyO3), C# (.NET 8)
MCP 70+ tools for AI assistants (HTTP + stdio)

Installation and Startup

HTTP Mode (Server)

# Build
cd mcp-server && cargo build --release

# Start
./target/release/mcp-ironbase-server

# Result:
# Server listening on https://0.0.0.0:8080 (TLS enabled)

Stdio Mode (Claude Desktop)

./target/release/mcp-ironbase-server --stdio

Query Operators - Comparison

Comparison operators for filtering values.

Operator Description Example
$eq Equals {"age": {"$eq": 25}} or {"age": 25}
$ne Not equals {"status": {"$ne": "deleted"}}
$gt Greater than {"price": {"$gt": 1000}}
$gte Greater or equal {"age": {"$gte": 18}}
$lt Less than {"score": {"$lt": 50}}
$lte Less or equal {"quantity": {"$lte": 10}}
$in In array {"status": {"$in": ["active", "pending"]}}
$nin Not in array {"role": {"$nin": ["banned", "deleted"]}} 
// Complex example: Active users aged 18-65
{
  "filter": {
    "age": {"$gte": 18, "$lte": 65},
    "status": {"$in": ["active", "verified"]},
    "deleted_at": {"$eq": null}
  }
}

Query Operators - Logical

Operator Description Example
$and All conditions true {"$and": [{...}, {...}]}
$or At least one true {"$or": [{...}, {...}]}
$not Negation {"age": {"$not": {"$lt": 18}}}
$nor None true {"$nor": [{...}, {...}]} 
// Admin OR moderator AND active
{
  "filter": {
    "$and": [
      {"$or": [
        {"role": "admin"},
        {"role": "moderator"}

      {"status": "active"}

Query Operators - String

$regex - Regular Expression

{"email": {"$regex": "@gmail\\.com$"}}

// Name starting with (case sensitive)

// Contains (case insensitive workaround: lowercase index)
{"name_lower": {"$regex": "smith"}}

Query Operators - Special

$fuzzy - Fuzzy Search

Similarity-based search for handling typos and variations.

// Simple fuzzy (default: jaro_winkler, threshold: 0.8)
{"name": {"$fuzzy": "jhon"}}

// Full configuration
{"name": {"$fuzzy": {
  "value": "john",
  "algorithm": "levenshtein",
  "threshold": 0.7
}}}

Algorithms:

Algorithm Description Best For
jaro_winkler Fast, prefix-sensitive Names, short text
levenshtein Edit distance General typos
damerau_levenshtein Edit distance + transposition Letter swaps ("john" vs "jhon")

$** - Wildcard (Recursive Descent)

Find field at any depth in the document.

// Find "status" field ANYWHERE in document
{"$**.status": "active"}

// Matches:
// {"status": "active"}                    ✓
// {"user": {"status": "active"}}          ✓
// {"data": {"info": {"status": "active"}}} ✓
⚠️ Performance

$** always performs a collection scan, cannot use indexes. Avoid on large collections.

Update Operators

Operator Description Example
$set Set field {"$set": {"name": "new name"}}
$inc Increment number {"$inc": {"counter": 1, "score": -5}}
$unset Remove field {"$unset": {"temp_field": ""}}
$push Add to array {"$push": {"tags": "new_tag"}}
$pull Remove from array {"$pull": {"tags": "old_tag"}}
$addToSet Add unique to array {"$addToSet": {"roles": "editor"}}
$pop Remove first/last {"$pop": {"queue": 1}} (1=last, -1=first)

Modify nested fields: {"$set": {"address.city": "Boston"}}

Pipeline Stages

Stage Description Example

$group Group and aggregate {"$group": {"_id": "$city", "count": {"$sum": 1}}}
$project Select/rename fields {"$project": {"name": 1, "total": "$amount"}}
$sort Sort results {"$sort": {"total": -1}}
$limit Limit results {"$limit": 10}
$skip Skip results {"$skip": 20}

│                                                                 │

RAG - Semantic Search

Semantic search with vLLM/BGE-M3 embeddings and HNSW indexing. The search tool automatically embeds the query server-side - a single MCP call for complete hybrid retrieval!

┌─────────────────────────────────────────────────────────────────────────────┐
│                            RAG PIPELINE                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. SETUP                                                                   │
│  ════════                                                                   │
│  rag_collection_create(collection: "kb", language: "english")               │
│         │                                                                   │
│         ├──▶ Collection: "kb"                                               │
│         ├──▶ HNSW index: 1024 dim, cosine                                   │
│         ├──▶ Fulltext index: english stemmer                                │
│         └──▶ Config: _system.rag                                            │
│                                                                             │
│  2. IMPORT                                                                  │
│  ═════════                                                                  │
│  rag_document_import(collection: "kb", content: "...", title: "Guide")      │
│         │                                                                   │
│         ├──▶ Chunking: 1000 char, 100 overlap                               │
│         ├──▶ Batch embedding: BGE-M3 1024-dim (vLLM)                        │
│         └──▶ Insert chunks with vectors                                     │
│                                                                             │
│  3. SEARCH (1 MCP CALL!)                                                    │
│  ════════════════════════                                                   │
│  search(collection: "kb", query: "database")                                │
│         │                                                                   │
│         ├──▶ AUTO-EMBED query ← KEY DIFFERENCE!                             │
│         ├──▶ Vector search (HNSW)                                           │
│         ├──▶ Fulltext search (BM25)                                         │
│         ├──▶ RRF fusion (k=20)                                              │
│         ├──▶ Reranking (phrase match, density)                              │
│         └──▶ Document-anchored grouping                                     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
💡 Single-call retrieval

The search tool automatically embeds the query server-side — a single MCP call, with no separate embed_text step.

RRF (Reciprocal Rank Fusion) Algorithm

Hybrid search combines vector and fulltext results using RRF:

score = vector_weight × 1/(k + vector_rank) + fulltext_weight × 1/(k + text_rank)

// Example (k=20, weights=0.5/0.5):
// doc1: vector_rank=1, text_rank=1
// score = 0.5 × 1/21 + 0.5 × 1/21 = 0.0476
// (weights and k are server-owned; not exposed by the search tool)

Reranking

Result scores are modified by 3 factors:

Factor Boost Condition
Exact phrase match ×1.3 Query > 10 chars and found
Keyword density ×1.0-1.1 Query word ratio in content
Length penalty ×0.8 Content < 100 chars

Durability Modes

Mode fsync Speed Data Loss on Crash
safe ✓ every op ~1-5K ops/sec 0
batch ✓ every N ops ~20-50K ops/sec Max N operations
unsafe ✗ ~50-100K ops/sec All uncommitted

│ limit=1000  │ limit=1000  │ limit=1000  │     │ limit=1000      │

// Skip/Limit pagination
{"filter": {}, "limit": 1000, "skip": 0}       // Page 1
{"filter": {}, "limit": 1000, "skip": 1000}    // Page 2
{"filter": {}, "limit": 1000, "skip": 2000}    // Page 3

// Cursor-based (faster for large skips)
{"filter": {"_id": {"$gt": "last_id"}}, "limit": 1000, "sort": [["_id", 1]]}

Index Strategy

💡 Index Tips
  • Index frequently filtered fields
  • Compound index: left-prefix rule (a, b) → can use for (a) too
  • Use explain() to check query plans
  • Sparse index for optional fields
  • Unique index for email, username fields

Avoiding OOM

🚨 Avoid
  • find({}, {}) on large collection without limit
  • Aggregation without $match on 100K+ documents
  • $push for unlimited array growth
💡 Recommended
  • Always use limit with find
  • Put $match at start of aggregation pipeline
  • Use projection for large results to select only needed fields
  • Stream processing with pagination

RAG Example - Semantic Search from Script

// RAG search
let results = db_hybrid_search("knowledge_base", "capital of Hungary");
for r in results {
    print("[" + r.score + "] " + r.doc_title + ": " + r.text);
}

// Import document
let result = db_rag_document_import(
    "knowledge_base",
    "budapest_info",
    "Budapest",
    "Budapest is the capital of Hungary..."
);
print("Created " + result.chunks_created + " chunks");

// Search with min_score filter
let filtered = db_hybrid_search("knowledge_base", "history", #{
    limit: 10,
    min_score: 0.6
});

RAG Tools (4 tools)

Semantic search with automatic query embedding. The search tool performs complete document-anchored hybrid retrieval in a single MCP call!

rag_collection_create - Create RAG Collection
