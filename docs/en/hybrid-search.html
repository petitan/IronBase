What is search?

search is the unified, document-anchored hybrid retrieval tool for RAG. It fuses BM25 full-text and HNSW vector results and returns ranked source documents, each with its relevant passages — optimized for a small LLM: no embeddings to pass, no engine metadata, token-budgeted output.

Intent-only surface

The retrieval mechanism — vector/text weights, RRF fusion, reranking, MMR diversity, chunk merging, thresholds — is server-owned. The tool deliberately exposes only intent (collection, query, filter, limit, format), so callers never have to tune knobs. Tuning happens inside the engine.

Supersedes hybrid_search / vector_search_filter

search replaces the older hybrid_search and vector_search_filter MCP tools (removed). The same RRF fusion engine powers it under the hood, but the per-call tuning parameters they exposed (search_mode, vector_weight, rrf_k, mode, match_scope, rerank, mmr_lambda, group_by_document, …) are no longer part of the tool surface. See Migration.

How it works (server-side)

A search call runs an internal pipeline you do not configure. The steps below are informational — they describe what the engine does, not parameters you set: 

query ─► (auto-embed) ─┬─► HNSW vector search ─┐
                       └─► BM25 fulltext       ┘
                                  │
                                  ▼
                       RRF fusion (Reciprocal Rank Fusion)
                                  │
                                  ▼
                       rerank (phrase / density / title / length)
                                  │
                                  ▼
                       adjacent-chunk merge (overlap dedup)
                                  │
                                  ▼
                       group by source document, token-budget passages
                                  │
                                  ▼
                       ranked documents (+ passages)
  • Auto-embed: the query is embedded server-side using the collection's configured provider (Ollama / vLLM / OpenAI). You never pass a vector.
  • RRF fusion: vector and lexical rankings are combined by Reciprocal Rank Fusion, robust to incomparable score scales.
  • Document anchoring: results are grouped by source document; each document carries its relevant, overlap-merged passages (no chunk internals).
  • Token budget: passages are capped; if the budget trims output, the response flags trimmed: true (a non-empty corpus never returns empty).

search Tool Reference

search — Document-anchored hybrid retrieval

Returns ranked source documents with their relevant passages for a natural-language query.

Parameters

ParameterTypeDefaultDescription
collection string required Collection to search.
query string required Natural-language query or keywords. Auto-embedded server-side.
filter object optional Structured metadata filter applied before retrieval, e.g. {"year": 2026, "customer": "X"}.
limit integer 5 Maximum number of documents to return.
format string "structured" "structured" = documents with passages; "context_block" = a single citation-marked text block ready to paste into a prompt.
debug boolean false Include a diagnostics block (stage, fusion, qualified doc count, total chunks).

Response Format

structured (default)

{
  "verdict": "unknown",
  "documents": [
    {
      "doc_id": "arajanlat-2026-001",
      "title": "BKV árajánlat",
      "relevance": 0.039,
      "passages": [
        {"text": "..."},
        {"text": "..."}
      ]
    }
  ],
  "count": 1,
  "trimmed": false
}
FieldDescription
verdictStage A always returns "unknown" (no absolute-relevance / abstention calibration yet).
documentsRanked source documents. Each has doc_id, document-level fields, relevance (fused score), and passages ({"text": ...} only — no engine internals).
countNumber of documents returned.
trimmedtrue if the token budget dropped some passages.
dropped_empty_documentsPresent only when qualified documents had no body text under the resolved text field (surfaced anomaly, never silently hidden).
diagnosticsPresent only with debug: true.

context_block

With format: "context_block", the documents array is replaced by a single context string — citation-marked ([doc_id] title), ready to paste into a prompt:

{
  "verdict": "unknown",
  "context": "[arajanlat-2026-001] BKV árajánlat\n...passage text...\n\n",
  "count": 1,
  "trimmed": false
}

Examples

Basic Search

{
  "name": "search",
  "arguments": {
    "collection": "rdocs",
    "query": "BKV Zrt árajánlat",
    "limit": 5
  }
}

Filtered Search

Narrow retrieval with a structured metadata filter applied before fusion:

{
  "name": "search",
  "arguments": {
    "collection": "rdocs",
    "query": "karbantartási díj",
    "filter": {"year": 2026, "customer": "BKV"},
    "limit": 5
  }
}

Context Block (for prompting)

{
  "name": "search",
  "arguments": {
    "collection": "rdocs",
    "query": "szállítási határidő",
    "format": "context_block"
  }
}

RAG Collection Setup + Search

1. Create RAG Collection

{
  "name": "rag_collection_create",
  "arguments": {
    "collection": "rdocs",
    "language": "hungarian",
    "text_fields": ["title", "customer"]
  }
}

2. Import Documents

{
  "name": "rag_document_import",
  "arguments": {
    "collection": "rdocs",
    "doc_id": "arajanlat-2026-001",
    "content": "...",
    "title": "BKV árajánlat",
    "if_exists": "replace"
  }
}

3. Search

{
  "name": "search",
  "arguments": {
    "collection": "rdocs",
    "query": "BKV árajánlat karbantartás"
  }
}
Multi-field is automatic

The fields configured at rag_collection_create time (text_fields) are searched automatically — the RAG config stores the list and search resolves it server-side. There is no per-call text_fields override.

Migration from hybrid_search

hybrid_search and vector_search_filter were removed. Map your calls to search as follows. Tuning parameters have no replacement — they are now decided by the engine.

Old (hybrid_search)Now (search)
collection, query, filter, limitsame
vector (explicit embedding)removed — query is always auto-embedded
search_mode, vector_weight, fulltext_weight, rrf_kremoved — server-owned fusion
mode, match_scope, text_fields, title_fieldremoved — resolved server-side from the RAG config
rerank, deduplicate, mmr_lambda, merge_chunksremoved — applied internally
group_by_document (flat vs grouped)always document-anchored; use format for output shape
response: results[] with _rrf_score/_final_score/…documents[] with relevance + passages (no internals)

Best Practices

  • Use a natural-language query — the engine handles both lexical and semantic matching.
  • Add a filter to bound the search space on large collections (100K+ chunks) before retrieval.
  • Keep limit small (default 5) for LLM prompting; passages are token-budgeted.
  • Use format: "context_block" when you want a ready-to-paste, citation-marked context for a prompt.
  • Set debug: true while developing to see diagnostics (qualified docs, total chunks, fusion stage).
